Since February 2026 · Xcelerium

Close to the silicon, shipping in C

Xcelerium is a Silicon Valley startup building on RISC-V. I joined in February 2026 through its Train-to-Hire programme and now work as a firmware engineer, from Pakistan, with the engineering team in San Jose half a day behind.

  • FFT accuracy: 1.2 dB to 25 dB

    Optimised the compute kernels behind an FFT routine, raising its signal-to-noise ratio from 1.2 dB to 25 dB.

  • Bugs below the debugger

    Tracked down low-level faults including cache-coherence problems, where the code looks right and the memory disagrees.

  • Tests that compare against a reference

    Wrote C tests for drivers, then used pytest to compare their output against values generated in Python, so regressions show up as a diff.

  • A new instruction, end to end

    Added an instruction to the toolchain so the compiler and assembler could use new hardware.

  • Boot, traps and UART

    A bare-metal bootloader, trap and interrupt handling, and a UART driver layer for the CVA6 core.

Beyond coursework · Final-year project

A CubeSat that checks its own solar panels

Most universities in Pakistan can't afford to build a CubeSat. I set out to build one cheaply, with an on-board curve tracer that records how its solar panels age in orbit.

Every part was made in-house. I modified a milling machine to make the circuit boards, designed the electronics, and wrote the firmware on Zephyr RTOS.

Why this programme

Open source is how I learned

I grew up without labs or mentors. Free tools, public datasheets and other people's open code are how I learned enough to build a satellite. Working on Ubuntu would let me give that back at a scale I couldn't reach on my own.

I also want to bring this work home. Free software on cheap hardware is how a school in a village like mine gets a working computer lab, and I want to help students in Pakistan find a path into engineering.
